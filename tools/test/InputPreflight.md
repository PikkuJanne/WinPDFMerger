# Input preflight native tests

The `InputPreflight` tier runs the copied real PowerShell entry point and actual
PDFtk 2.02 on owned synthetic inputs. PDFtk, Ghostscript 10.08.0 and their
companion DLLs must match the approved acquisition receipts. Ghostscript is used
only to create an original linearized development fixture. The explicitly
selected development Python runs an
independent pypdfium2 5.13.0 / PDFium 153.0.7999.0 reader; no package is installed.
Python and PDFium remain test dependencies and are never application engines.

```powershell
& $selectedShell -NoProfile -ExecutionPolicy RemoteSigned -File tools/test/Invoke-Tests.ps1 `
    -PesterModulePath $pesterManifest -Tier InputPreflight `
    -PdftkPath $pdftkExecutable -GhostscriptPath $ghostscriptExecutable `
    -PythonPath $developmentPython
```

Select the approved Windows PowerShell 5.1 and supported portable PowerShell 7.6.6
hosts explicitly and run each separately as a standard user. The native tier
fails closed when the required environment or pinned oracle is unavailable.
Only the already authorized test-child execution policy is used. Child-only PATH
and common-location overrides make optional Ghostscript absent for these cases.

AC025 fixtures include zero bytes, the first 80 bytes of numbered `2.pdf`, a
91-byte PDF with a catalog referring to missing Pages object 99, plain text with
misleading digits and a `.pdf` suffix, and actual PDFtk-generated user-password
and owner-password protected files. A genuine zero-page PDF also checks that a
successful native exit cannot provide a positive inventory. Its exact 311 bytes
are embedded from the original pypdf 6.10.0 characterization, with a fixed hash;
the test does not need pypdf installed. Every rejected file sits between two
valid inputs. The complete ordered list remains logged, the offending filename
is reported, and no valid subset is merged or master/email PDF created.

Copies of the numbered fixture with missing EOF, the final 40 bytes removed,
final startxref changed to zero, a broken conventional xref keyword, or trailing
nonwhitespace exercise the bounded byte-envelope rejection. PDFtk was measured
accepting the missing-EOF, zero-startxref, broken-xref and trailing-data variants;
a successful native parse alone does not satisfy
the input contract. The guard reads a short header, final footer window and xref
target prefix, then PDFtk still provides document-data inspection. It is not a
complete PDF parser or proof that every internal object is intact.

The development-only `generate_pdf_envelope_fixtures.py` writes original CR
structural/footer, incremental and PDF 1.5 cross-reference-stream files, plus an actual Ghostscript
FastWebView linearized file. Each positive input retains its independently read
visible identifier and expected page count. The CR fixture uses the required
LF stream opening while keeping CR structural/footer line endings. Multiple EOF/startxref records and
the linearized file's earlier dummy zero must not override the final record.
Its manifest records generated bytes/hashes, offsets and the fixed bounded GS
command/results. Harmless native warnings remain in the logs and do not decide
success independently of exit state and the labeled positive count.

AC026 checks one input, `1,01,2,10`, and multiple numeric segments. Per-input
positive page counts and the expected total are compared with known fixture
metadata, while the original numbered input lines are compared with explicit
expected paths. The independent reader inspects the produced master for every
visible T03 identifier in order, including deliberately repeated identifiers.
This is narrow page/order evidence, not complete preservation or visual fidelity.

Real metadata containing `InfoValue: NumberOfPages: 999999` must not invent a
count. A separate same-length Title edit containing a PDF octal newline makes
actual PDFtk emit a counterfeit anchored `NumberOfPages` label before the real
label. Ambiguous data fails the complete job. Unit tests cover controlled parser
warnings and source-change faults separately. An actual exclusive file lock
fails at the read-only envelope open before native launch; its observed elapsed
time and null native result are recorded. It is a sharing denial, not an
ACL-denial or native timeout claim. The accepted metadata case exercises an
actual native inspection with an injectable three-second bound.

The fixtures demonstrate specific rejected damage and protected-input cases.
The bounded guard and PDFtk can still accept some internally damaged files and
some readable encryption;
these tests do not claim universal corruption or encryption detection. Sources
and the existing foreign-output sentinel retain hashes, lengths, modification
times and attributes. Length/mtime checks do not provide a transactional snapshot
against another process editing source documents.

Pester XML/summary reports and `tests/.work/input-preflight/<GUID>` receipts retain
the actual command/result streams, ordered expectations, source snapshots,
inspection results and independent reader results. The fixed reader and its
expectation JSON live only under this ignored owned run directory. Its hash and
Python/PDFium versions are recorded. T12 staging and T13 master validation remain
separate work; a successful reader does not certify an untrusted PDF as safe.
